## 前言

### 编写目的

此文档的编写目的是让用户、设计人员、开发人员和测试人员，对投票系统的整体功能、技术和数据等方面需求的初始规定有一个共同的理解，使之成为系统后续设计和开发工作的基础。

### 项目名称

新版东方人物人气投票（投票系统）

### 术语定义

| 序号 | 名称 | 描述 |
| --- | --- | --- |
| 1 | 主问卷 | 用户社群调研、收集社群基本信息的问卷 |
| 2 | 分问卷 | 主问卷的附属问卷 |
| 3 | 额外问卷 | 对于社群某一个角度，深入调研的问卷 |
| 4 | 问题组 | 用户填写问题的基本单位，具备“隐藏”“显示问题组中的某个问题”两种状态 |
| 5 | 相关问题（related） | 在同一个问卷中，选择了某个问题的某个选项之后，本问卷中额外需要用户回答的问题 |
| 6 | 互斥选项（mutex） | 在同一个问卷中，选择了某个问题的某个选项之后，本问题/本问卷的某个其他问题会被清除勾选/隐去选择的选项 |
| 7 | 选项组（Group） | 问卷的多选题中，互斥的若干个选项 |
| 8 | 票 | 参与投票的基本载体，代表一个账号在某个部门的完整投票权利，一张票包含多个票位 |
| 9 | 票位 | 系统中投票的基本组成单位，每个票位可以容纳一个投票对象（角色/音乐/CP），分为本命票位和普通票位 |

## 系统功能

### 倒计时页面 & 结束页面

#### 倒计时页面

- 需求描述：正式投票前的倒计时页面
- 目标路径：投票系统-倒计时页面
- 权限范围：所有用户
- 页面内容：
  - 标题名称：中文东方人气投票 第XX回，其中 XX 代表当前举办回数
  - 结束时长：精确到秒，实时刷新，注意结束时间以北京时间计算，其他时区需要考虑时差
- 补充说明：该页面在 `https://touhou.vote` 正式解析至前端 vote 分支、但尚未正式开始投票时展示

#### 结束页面

- 需求描述：正式投票结束后的展示页面
- 目标路径：投票系统-首页
- 权限范围：所有用户
- 页面内容：
  - 标题名称：中文东方人气投票 第XX回，其中 XX 代表当前举办回数
  - 用户设置入口：点击链接后跳转至“用户设置”页面
- 补充说明：该页面在 `https://touhou.vote` 尚未解析至前端 result 分支、但投票已经结束时展示

### 首页

#### 投票首页

- 需求描述：展示投票信息
- 目标路径：投票系统-首页
- 权限范围：所有用户
- 页面内容：
  - 标题名称：同倒计时页面
  - 登录入口：点击弹出登录框
  - 结束时长：同倒计时页面
  - 介绍文本：文本参考页面图片
  - 详细介绍：文本参考页面图片，其中官号链接、QQ 反馈群支持链接跳转
- 补充说明：本页面仅在“投票正式开始”期间适用

#### 登录框

- 需求描述：提供登录入口
- 目标路径：投票系统-首页
- 权限范围：所有用户
- 页面内容：
  - 打开登录框后，首先展示验证码登录模式
  - 国内手机号/邮箱输入框：支持手机号/邮箱格式校验，失败提示“请输入正确格式的邮箱或手机号！(不支持海外手机号)”
  - 获取按钮：点击后先校验手机号/邮箱格式，成功后发送验证码并进入 120 秒冷却
  - 验证码输入框：无校验，无内容提示“请输入验证码！”
  - 开始投票按钮：点击后校验手机号/邮箱和验证码存在性，校验通过后登录
  - 点击“使用旧版账号密码登录”后，展示旧版账号密码登录框
  - 旧版登录包含邮箱、密码和登录按钮
- 补充说明：
  - 新版系统不再提供账号注册服务，用户直接通过验证码登录
  - 旧版系统账户密码忘记时，直接通过曾绑定邮箱使用邮箱验证码登录，密码可在登录后的用户中心修改

### 个人中心

进入登录之后便会进入个人页面，页面设计应以尽可能让用户明白投票下一步操作为优先考虑。

#### 投票入口

用户进行下一步操作的入口，必须醒目，分为以下几种情况：

- 未进行任何操作的时候：填写问卷（必填项目）
- 问卷（必填项目）完成后：填写问卷（可选项目）、填写问卷修改（必填项目）
- 问卷（必填项目填写完毕且可选项目填写完至少其中一个）：投票入口、填写问卷修改（必选项目&可选项目）
- 全部填写完毕：投票内容修改、填写问卷修改（必选项目&可选项目）

注：未开放的入口可以用灰色表示暂时不可进入，而不是直接隐藏。

- 需求描述：展示投票的各个部分的入口
- 目标路径：投票系统-个人中心
- 权限范围：已登录用户
- 页面内容：
  - 填写问卷、参与投票和作品提名的入口，并展示完成 Tag
  - 若问卷未完成，则参与投票、作品提名入口不可进入
  - 桌面端还需要展示每个入口的下属模块入口
  - 页面右上角有用户头像，点击后出现用户菜单：
    - 用户头像：默认头像
    - 用户名称：优先级为用户名、登录时使用的手机号后四位、登录时使用的邮箱
    - 账号设置：跳转到账号设置页面
    - 退出登录：删除所有 local storage 暂存数据并回到投票首页

#### 用户设置

- 需求描述：用户数据的修改
- 目标路径：投票系统-个人中心-用户设置
- 权限范围：已登录用户
- 页面内容：
  - 用户名：同投票入口中的用户名称
  - 用户头像：默认头像
  - 注册时间：展示账户注册日期
  - 修改用户名：
    - 点击后弹出用户名修改窗口
    - 修改成功提示“修改成功,请重新登录！”，之后退出登录
  - 邮箱：已绑定则展示绑定邮箱，否则显示“未绑定”
  - 手机号：已绑定默认仅展示后四位，否则显示“未绑定”
  - 密码：若已有密码显示“已设置”，否则显示“未设置”
  - 修改密码：
    - 已设置密码时需填写旧密码
    - 新密码最长 30 字符
    - 重复新密码必须一致
    - 成功后提示“修改成功！”
    - 旧密码错误时提示“旧密码输入错误！”
  - 退出登录：效果同投票入口中的退出登录
  - 若投票已结束，可在结束页面进入个人中心，对绑定手机号和邮箱进行修改：
    - 修改邮箱 / 去绑定邮箱
    - 修改手机号 / 去绑定手机号
- 补充说明：
  - TODO：支持头像修改
  - 邮箱/手机号与账户一一对应，修改时需要验证是否已绑定账户

## 调查问卷

### 问卷形式

本节为概念解释，非需求内容，强烈建议认真参阅术语定义部分。

#### 1. 调查问卷

原文包含“调查问卷设计逻辑”示意图。

- 问卷分为主问卷和额外问卷
- 主问卷包含必填问卷和分问卷
- 分问卷包含官方作品问卷和二次创作问卷
- 用户完成必填问卷和分问卷的至少一个问卷，则视为主问卷填写完成
- 额外问卷包含：
  - 同人作品相关问卷
  - 官作游戏相关问卷
  - 展会与手游相关问卷
  - 正版盗版相关问卷
  - 社群相关 / 主办方附加问卷
- 用户完成至少一个额外问卷，则视为额外问卷填写完成
- 主问卷和额外问卷均填写完成后，用户才可以进行正式投票

#### 2. 单个问卷

原文包含“单个问卷设计”示意图。

- 单个问卷由多个问题组组成
- 用户从第一个问题组的第一个问题开始作答
- 第一个问题组必定仅有一个问题
- 根据选项的 `related` 属性决定后续问题展示逻辑

具体规则：

- 若选项的 `related` 指向后续某问题组第 0 个问题，或该问题组初始问题为第 0 个问题，则该问题组默认隐藏
- 若选项的 `related` 指向后续某问题组第非 0 个问题，则展示 `related` 指向的问题
- 若问题组初始问题非第 0 个问题，则默认展示第 1 个问题

示例答题路径：

- `【1-1】 -> 【2-1】 -> 【4-1】 -> 【N-1】`
- `【1-1】 -> 【2-2】 -> 【3-1】 -> 【4-1】 -> 【N-1】`
- `【1-1】 -> 【2-3】 -> 【3-1】 -> 【4-1】 -> 【N-2】`

当用户回答完该问卷下可以回答的所有问题后，视为该问卷完成。

#### 3. 单个问题

原文包含“单个问题设计”示意图。

- 问题共有三种类型：
  - 单选（Single）
  - 多选（Multiple）
  - 输入（Input）
- 对于单选和多选问题，选项存在互斥关系
- 多选题中，互斥也可能基于不同 Group 判断
- 当用户完成：
  - 单选：选择一个选项
  - 多选：至少选择一个选项
  - 输入：输入任意内容
  时，视为该问题完成填写

#### 4. ID

基本问卷、每个子问卷、题目和选项均有唯一 ID。

示例：`1 2 03 4 05`

- 第 1 位：问卷类型
  - `1` = 主问卷
  - `2` = 额外问卷
- 第 2 位：问卷子分类
  - 主问卷：
    - `1` = 必填问卷
    - `2` = 官作分问卷
    - `3` = 二创分问卷
  - 额外问卷：
    - `1` = 二创深入了解问卷
    - `2` = 官作通关情况深入了解问卷
    - `3` = 展会观众与商业授权手游深入了解
    - `4` = 正版&盗版深入了解问卷
    - `5` = 主办方附加问卷
- 第 3-4 位：问题组序号
- 第 5 位：单个问题组中问题的顺序
- 第 6-7 位：单选 / 多选问题中选项的序号

### 问卷编辑

- 需求描述：问卷编辑页面
- 目标路径：`/`
- 权限范围：开发人员
- 功能要求：
  - 页面读取投票系统已有问卷数据并可视化呈现
  - 开发人员根据 Word 版问卷描述编辑问卷数据
  - 需要支持：
    - 问卷 / 问题 / 名称呈现
    - 问卷 ID 呈现
    - 问题选项呈现，包括 `related`、`mutex`、`group`
    - 问题组 / 问题 / 选项插入
    - 问题属性编辑（Single, Multiple, Input）
    - `related`、`mutex` 编辑
  - 基本校验：
    - 校验问题种类是否合法
    - 校验所有选项内容不为空，且选项组为大于等于 0 的整数
    - 校验所有 `related` 合法（5 位，且拥有对应问题）
    - 校验所有 `mutex` 合法（7 位，且拥有对应选项）
    - 校验非 Input 类型选项列表不为空
    - 校验问题库里的某一个问题列表不为空
- 补充说明：
  - 该页面需要手动输入路径，在已登录状态下进入
  - 未做移动端适配，建议宽度不低于 1400px
  - 无法校验 `related` / `mutex` 是否指向前方问题组 / 选项，需要人工复验

### 问卷选择

- 需求描述：问卷选择页面
- 目标路径：投票系统-个人中心-问卷选择
- 权限范围：已登录用户
- 页面内容：
  - 点击“填写问卷”后展示所有问卷填写入口
  - 每个入口展示问卷标题、描述和填写情况
  - 问卷按种类区分，并提示填写规则：
    - 主要问卷：至少选择填写两个主要问卷
    - 额外问卷：至少选择填写一个额外问卷
  - 用户点击入口后进入问卷填写页面

### 问卷填写

#### 问卷填写

- 需求描述：填写调查问卷
- 目标路径：投票系统-个人中心-问卷选择-问卷填写
- 权限范围：已登录用户
- 页面内容：
  - 页面顶端导航栏展示当前问卷名称
  - 导航栏左侧“<”按钮：退出问卷填写页面，点击后弹出确认框
  - 问卷问题框包含：
    - 问题编号
    - 题目
    - 题目类型：单选 / 多选 / 输入
    - 选项列表或输入框
    - 回答进度条
  - 下方按钮：
    - 上一题
    - 下一题
  - 问卷完成后出现“提交”按钮
  - 提交后根据是否完成整个调查问卷，给出不同提示
  - 完成后支持：
    - “休息一下，返回主页面”
    - “我还想继续填写/修改问卷！”
- 补充说明：
  - 问题序号不是问题组原始序号，而是当前可见问题的实时顺序
  - 对于单选题，选择完选项后自动跳转到下一题
  - 问卷内容在每次提交时保存至本地存储
  - 桌面端右下角还会有“返回主页”按钮

#### 问题选择器

- 需求描述：切换调查问卷的问题
- 目标路径：投票系统-个人中心-问卷选择-问卷填写
- 权限范围：已登录用户
- 页面内容：
  - 问卷名称
  - 问卷回答情况（已回答问题数量 / 总问题数量）
  - 问卷下属问题编号
  - 已回答和未回答的问题在样式上区分
  - 点击问题编号后跳转到对应问题
